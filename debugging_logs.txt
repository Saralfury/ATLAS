# ATLAS Debugging & Engineering Audit

## Session Summary

---

# Initial State

The ATLAS project was functionally operational but suffered from multiple visualization and runtime issues.

Observed problems:

* India map rendered as a placeholder polygon.
* Maritime shipping routes crossed mainland India.
* Framer Motion opacity warnings.
* Browser occasionally reported "Backend offline."
* Previous forensic audit had identified render-loop risks.
* Heavy rendering occasionally froze the interface.

---

# Phase 1 — India Map Investigation

## Discovery

`public/india.json`

contained only a tiny placeholder polygon (~332 bytes).

It was never intended to be the production coastline.

The rendering pipeline itself was correct.

Problem:

```
GeoJSON Asset
↓

Placeholder Polygon

↓

Placeholder India
```

### Resolution

Replaced the placeholder with a proper high-resolution India GeoJSON.

No rendering architecture changes were required.

---

# Phase 2 — Projection Investigation

Initially suspected:

* projection mismatch
* react-simple-maps issue
* geoMercator mismatch

Investigation showed:

Ports already aligned correctly.

Endpoints matched coastline.

Only route geometry appeared incorrect.

### Conclusion

Projection was NOT the problem.

Projection remained untouched.

# Phase 10 — React Hook Investigation

Historical forensic audit already highlighted:

```
usePortData
```

as a high-risk location.

Inspection confirmed the hook had previously depended on:

```
riskData
```

while simultaneously updating

```
riskData
```

This created:

```
Fetch

↓

setRiskData()

↓

riskData changes

↓

useEffect runs again

↓

Fetch

↓

repeat forever
```

Classic render/fetch loop.

---

# Fix

Dependency array changed to

```
[setRiskData]
```

instead of

```
[riskData]
```

Result:

Loop eliminated.

---

# Phase 11 — Why "Backend Offline" Appeared

Important finding:

Backend was healthy.

However:

Hundreds of frontend fetches overwhelmed:

* browser networking
* rendering thread
* request queue

Eventually:

```
TypeError

↓

Failed to fetch

↓

API wrapper

↓

Backend offline
```

The backend was blamed even though it never crashed.

After:

---

# Engineering Lessons

1. Never assume the backend is broken because the frontend reports it.
2. Verify health endpoints before changing backend code.
3. A React dependency mistake can masquerade as an infrastructure outage.
4. Heavy rendering can expose latent state-management bugs.
5. Visualization data should remain separate from simulation data.
6. Always commit after reaching a stable milestone.
7. Diagnose with evidence rather than rewriting architecture.
